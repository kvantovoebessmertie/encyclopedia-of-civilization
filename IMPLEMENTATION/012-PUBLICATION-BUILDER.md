# 012 — Сборщик публикаций

## Энциклопедия цивилизации

Версия: 0.1  
Класс: Implementation Specification  
Статус: рабочая нормативная спецификация  
Дата: 29 сентября 2026 года

---

## 1. Назначение

Publication Builder преобразует выбранное и проверенное множество канонических Record в производное представление:

- сайт;
- PDF;
- печатный макет;
- offline reader;
- книгу;
- учебный материал;
- API representation;
- другой формат.

Publication Builder не является каноническим хранилищем.

## 2. Архитектура

    Canonical Records
          ↓
       selection
          ↓
     composition
          ↓
      validation
          ↓
   Publication Builder
          ↓
   derived publication

Публикация должна ссылаться на версии исходных Record.

## 3. Selection

Выбор должен быть воспроизводимым.

Он может основываться на:

- Record IDs;
- версиях;
- типах;
- Scope;
- Context;
- языке;
- статусе;
- заданной композиции;
- явно определённых фильтрах.

Критерии отбора должны сохраняться вместе с результатом сборки.

## 4. Composition

Composition определяет:

- порядок;
- группировку;
- заголовки;
- навигацию;
- взаимные ссылки;
- уровень детализации;
- формат представления.

Composition не изменяет исходную Record.

## 5. Version pinning

Публикация должна фиксировать:

- record_id;
- record_version;
- type_version;
- schema;
- применимые Standard;
- версию Publication Builder.

Если используется текущая версия, это должно быть явно указано как политика сборки.

## 6. Semantic preservation

Сборщик не должен:

- менять Claim;
- менять Evidence Use;
- менять Assessment;
- удалять uncertainty;
- менять Scope;
- менять Context;
- превращать publication_status в epistemic status.

Сокращение текста допустимо только как производное представление с сохранением ссылки на исходное содержание и правил сокращения.

## 7. Translation

Перевод является производным представлением.

Оригинал и перевод должны быть связаны.

Изменение перевода не должно изменять исходную Record.

## 8. Citations

Публикация должна позволять установить происхождение существенного содержания.

Для утверждений должны быть доступны соответствующие ссылки на Evidence Use, Source, Assessment или другие применимые Record.

## 9. Integrity

Каждая публикационная сборка должна иметь:

- build_id;
- дату;
- версии инструментов;
- набор входных Record;
- digest результата;
- статус сборки.

Digest публикации не доказывает истинность её содержания.

## 10. Reproducibility

Одинаковые:

- входные версии;
- Composition;
- настройки;
- версия Builder

должны давать эквивалентный результат.

Если результат намеренно недетерминирован, причина должна быть определена.

## 11. Publication states

Минимально:

- draft;
- preview;
- released;
- withdrawn.

Publication state не является publication_status исходной Record и не заменяет его.

## 12. Failed build

При ошибке сборки публикация не должна объявляться released.

Частично созданный артефакт должен быть помечен как неполный либо удалён по политике сборки.

## 13. Offline publication

Builder должен поддерживать локальную сборку из Portable Package, если пакет содержит необходимые компоненты.

Внешний сервер не должен быть обязательным для self-contained package.

## 14. Security

Builder не должен:

- исполнять Record как код;
- доверять HTML/Markdown как безопасному коду;
- автоматически выполнять внешние ссылки;
- позволять path traversal;
- загружать произвольные ресурсы без политики.

Выход должен быть безопасно экранирован для конкретного формата.

## 15. Tests

- B01 — публикация строится из фиксированных версий;
- B02 — исходные Record не изменяются;
- B03 — citations сохраняются;
- B04 — Scope сохраняется;
- B05 — Context сохраняется;
- B06 — uncertainty сохраняется;
- B07 — перевод не изменяет оригинал;
- B08 — failed build не становится released;
- B09 — build digest воспроизводим;
- B10 — offline build работает;
- B11 — withdrawn source не скрывается молча;
- B12 — path traversal блокируется.

Стресс-тесты B13–B20:

- большой граф;
- много языков;
- большая книга;
- большое число цитат;
- длинные Unicode-тексты;
- отсутствующая зависимость;
- несовместимые версии;
- повторная сборка.

## 16. Инварианты

1. Публикация производна от Record.
2. Публикация не изменяет Record.
3. Версия источника фиксируется.
4. Перевод не заменяет оригинал.
5. Digest не равен truth.
6. Failed build не является released.
7. Publication state не равен publication_status Record.
8. Offline build не требует исходного сервера для self-contained package.

## 17. Критерии готовности

012 готов, если определены selection, composition, version pinning, citations, translation, integrity, reproducibility, publication states, offline build, security и tests.

## 18. Статус

Документ не определяет конкретный формат сайта, PDF или печатного макета.
