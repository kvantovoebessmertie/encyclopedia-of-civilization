# 004 — Стандарт использования свидетельств

**Проект:** Энциклопедия цивилизации  
**Версия:** 0.2  
**Статус:** рабочий нормативный стандарт  
**Идентификатор:** `004-EVIDENCE-USE`

---

## 1. Назначение

Настоящий стандарт определяет, как проект фиксирует использование материала источника в качестве свидетельства относительно конкретного утверждения.

Стандарт устанавливает:

- границы использования свидетельства;
- обязательную связь с идентичностью источника;
- обязательную область использования материала;
- связь с одним целевым утверждением;
- два базовых направления свидетельства;
- правила разрешения исторически значимого состояния источника;
- правила для поиска, наблюдения, отрицательного свидетельства и отсутствия результата;
- правила для преобразований, OCR и составных источников;
- различие между использованием свидетельства и оценкой;
- требования к происхождению, сохранению истории и восстановимости;
- требования к дедупликации, зависимости и независимости;
- критерии соответствия и сквозного восстановления цепочки.

Настоящий стандарт специализирует `STANDARD/001-RECORD.md`, использует `STANDARD/002-CLAIM.md` и `STANDARD/003-SOURCE.md` и не переопределяет их семантику.

---

## 2. Нормативный язык

Используются модальности:

- **ДОЛЖЕН / ДОЛЖНА / ДОЛЖНО / ДОЛЖНЫ** — обязательное требование;
- **НЕ ДОЛЖЕН / НЕ ДОЛЖНА / НЕ ДОЛЖНО / НЕ ДОЛЖНЫ** — обязательный запрет;
- **СЛЕДУЕТ** — сильная рекомендация;
- **НЕ СЛЕДУЕТ** — сильная рекомендация избегать указанного поведения;
- **МОЖЕТ / МОГУТ** — допустимая возможность.

Иностранные обозначения допускаются только как технические идентификаторы, машинные значения, форматы и пути к файлам.

Машинные значения базовой модели:

```text
supports
contradicts
UNKNOWN
UNRESOLVED
NOT APPLICABLE
```

Неизвестное значение ДОЛЖНО оставаться неизвестным.

Отсутствие данных НЕ ДОЛЖНО автоматически превращаться в отрицательное значение.

---

## 3. Определение и границы

### 3.1. Использование свидетельства

**Использование свидетельства** — специализированная запись, фиксирующая конкретное использование определённого материала источника в отношении одного конкретного утверждения.

Использование свидетельства:

- НЕ является самим источником;
- НЕ является самим утверждением;
- НЕ является оценкой;
- НЕ является выводом;
- НЕ устанавливает автоматически истинность утверждения;
- НЕ содержит автоматически оценку силы, надёжности или независимости свидетельства.

Использование свидетельства является специализированным типом записи и наследует общие требования `STANDARD/001-RECORD.md`.

### 3.2. Минимальное ядро

Каждое атомарное использование свидетельства ДОЛЖНО разрешаться как:

```text
Запись
  +
одна Идентичность источника
  +
одна определённая Область свидетельства
  +
одно Целевое утверждение
  +
одна Роль свидетельства
```

Дополнительный контекст ДОЛЖЕН представляться только в той мере, в какой он необходим для однозначного разрешения использования свидетельства, его исторического состояния или его интерпретации.

### 3.3. Источник

Источник определяется `STANDARD/003-SOURCE.md`.

Ссылка на источник ДОЛЖНА разрешаться к идентичности источника.

Наличие записи источника само по себе НЕ делает материал свидетельством.

### 3.4. Целевое утверждение

**Целевое утверждение** — конкретное утверждение, относительно которого используется свидетельство.

Одна атомарная запись использования свидетельства ДОЛЖНА иметь ровно одно целевое утверждение.

Если один материал используется для нескольких утверждений, для каждого утверждения СЛЕДУЕТ создавать отдельную запись использования свидетельства.

### 3.5. Роль свидетельства

В ядре допускаются ровно две роли:

```text
supports
contradicts
```

Они означают соответственно:

- материал в данном использовании поддерживает целевое утверждение;
- материал в данном использовании противоречит целевому утверждению.

Сила, надёжность, независимость, уверенность, качество и степень убедительности НЕ являются ролями свидетельства. Они относятся к оценке.

Ограничение, уточнение, контекстуализация и логическое следствие НЕ ДОЛЖНЫ вводиться как дополнительные базовые роли.

---

## 4. Область свидетельства

### 4.1. Обязательность области

**Область свидетельства** — определённый материал источника, который фактически используется в данном свидетельстве.

Область ДОЛЖНА быть семантически определена.

Отсутствие технического локатора НЕ означает автоматически использование всего источника.

### 4.2. Материализация

Область МОЖЕТ быть выражена через:

- компонент;
- фрагмент;
- диапазон;
- цитируемый участок;
- наблюдаемое событие;
- измерение;
- изображение;
- аудио- или видеосегмент;
- структурный элемент;
- иной способ, определённый источником.

Не каждый технический локатор требует отдельной сущности.

### 4.3. Составная область

Несколько частей МОГУТ входить в одну область только тогда, когда вместе они образуют один связный доказательный материал для одного целевого утверждения.

Если части используются как разные доказательные основания или относятся к разным утверждениям, их СЛЕДУЕТ представлять отдельными использованиями свидетельства.

### 4.4. Неопределённая область

Если исторически известно, что источник использовался, но точная область неизвестна, запись МОЖЕТ сохранять такое использование при явном представлении неизвестности.

Неизвестная область НЕ ДОЛЖНА заменяться предположением о всём источнике.

---

## 5. Контекст разрешения источника

### 5.1. Контекст источника

**Контекст источника** — контекст, необходимый для разрешения того, какой именно источник и какое его состояние использовались.

Контекст источника не обязан становиться самостоятельной базовой сущностью.

Он МОЖЕТ включать только материально необходимые уровни:

- идентичность источника;
- состояние источника;
- выражение;
- представление;
- экземпляр;
- компонент;
- якорь;
- локатор;
- носитель;
- иной контекст, необходимый для разрешения.

### 5.2. Идентичность источника

Контекст ДОЛЖЕН разрешаться к одной идентичности источника.

Если идентичность спорна или неизвестна, это ДОЛЖНО оставаться явно представимым.

Ссылка на запись источника НЕ доказывает автоматически идентичность реального источника.

### 5.3. Состояние источника

**Состояние источника** — исторически или содержательно значимое состояние самого источника.

Версия записи источника НЕ равна состоянию источника автоматически.

Текущая запись источника НЕ ДОЛЖНА молча подменять исторически использованное состояние.

Если изменение состояния материально влияет на свидетельство, использованное состояние ДОЛЖНО оставаться разрешимым.

### 5.4. Другие уровни

Если свидетельство зависит от конкретного выражения, представления, экземпляра, компонента или носителя, соответствующий уровень ДОЛЖЕН сохраняться.

Если такой уровень не имеет материального значения, его отдельная фиксация НЕ обязательна.

---

## 6. Историческое использование

Историческая запись использования свидетельства ДОЛЖНА сохраняться даже при последующей утрате или недоступности источника, если идентичность и область использования могут быть разрешены настолько, насколько это известно.

Позднейшее изменение источника НЕ ДОЛЖНО переписывать исторический смысл использования свидетельства.

Изменение оценки свидетельства НЕ ДОЛЖНО автоматически создавать новую версию источника.

Изменение состояния источника НЕ ДОЛЖНО автоматически создавать новую запись использования свидетельства, если историческое использование остаётся тем же.

---

## 7. Поиск, наблюдение и отрицательное свидетельство

### 7.1. Результат поиска

Результат поиска, извлечения, наблюдения или запроса НЕ становится использованием свидетельства автоматически.

Он МОЖЕТ стать использованием свидетельства, если представлены:

- идентичность источника;
- область свидетельства;
- целевое утверждение;
- роль свидетельства.

### 7.2. Отрицательное свидетельство

«Не найдено» НЕ является третьей базовой ролью.

Отсутствие обнаружения может иметь значение свидетельства только при определённых условиях поиска или наблюдения.

Для материально значимого отрицательного свидетельства СЛЕДУЕТ сохранять:

- что искалось или наблюдалось;
- область поиска или наблюдения;
- релевантные условия;
- период или момент;
- известную возможность обнаружения;
- результат;
- ограничения результата.

«Не найдено» НЕ ДОЛЖНО автоматически означать «отсутствует».

### 7.3. Условия обнаружения

Если вывод об отсутствии зависит от того, что объект должен был быть обнаружим, соответствующие условия ДОЛЖНЫ быть представлены либо непосредственно, либо через разрешимые записи контекста.

Независимо спорные предпосылки поиска или наблюдения СЛЕДУЕТ представлять как отдельные утверждения, оценки или выводы, если они сами являются предметом знания.

---

## 8. Преобразования и производные представления

Если использованный материал получен через преобразование:

```text
исходный материал
      ↓
копия / оцифровка / преобразование
      ↓
представление
      ↓
область свидетельства
```

цепочка производности ДОЛЖНА сохраняться настолько, насколько она материально влияет на смысл или проверяемость свидетельства.

OCR НЕ является автоматически оригинальным источником.

Результат OCR МОЖЕТ использоваться как область свидетельства, но при материальном риске СЛЕДУЕТ сохранять связь с исходным представлением и характер преобразования.

Преобразование с потерями НЕ ДОЛЖНО скрываться под видом полного совпадения с исходником.

---

## 9. Составные источники

Компонент источника МОЖЕТ использоваться как область свидетельства без превращения его автоматически в самостоятельный источник.

Если компонент имеет самостоятельную идентичность, он НЕ ДОЛЖЕН сворачиваться в безымянный фрагмент только ради удобства.

Происхождение целого НЕ переносится автоматически на каждый компонент.

Если свидетельство зависит от происхождения конкретного компонента, соответствующая связь ДОЛЖНА сохраняться.

---

## 10. Зависимость и независимость

Использование свидетельства НЕ ДОЛЖНО содержать универсальный базовый признак `independent=true` как замену анализу происхождения и зависимости.

Независимость — свойство отношения между свидетельствами, их источниками, происхождением и соответствующим анализом.

Два использования свидетельства:

- МОГУТ быть разными;
- МОГУТ происходить из одного источника;
- МОГУТ происходить из разных представлений одного источника;
- МОГУТ зависеть от общего предка;
- МОГУТ быть независимыми;
- МОГУТ иметь неизвестную степень зависимости.

Различие записей НЕ доказывает независимость.

Разные источники НЕ являются автоматически независимыми.

Повторение одного сообщения НЕ является автоматически множеством независимых свидетельств.

Оценка независимости относится к `005-ASSESSMENT` и связанным моделям происхождения, а не к базовой роли свидетельства.

---

## 11. Цитирование и цепочки свидетельств

Цитирование источника НЕ доказывает производность его содержания.

Цепочка цитирования НЕ является автоматически цепочкой независимых свидетельств.

Если источник сообщает утверждение другого источника, это ДОЛЖНО сохранять различие между:

- сообщённым утверждением;
- источником, сообщающим его;
- источником, на который ссылаются;
- доказательным использованием;
- оценкой зависимости.

Циклическая сеть ссылок сама по себе НЕ является ошибкой.

Циклическая сеть становится проблемой, если доказательная поддержка целевого утверждения в конечном счёте зависит только от замкнутого круга без достаточного внешнего или независимого основания.

---

## 12. Границы с оценкой

Использование свидетельства фиксирует **что и как использовано**, а не **насколько это надёжно или убедительно**.

Следующие свойства НЕ ДОЛЖНЫ помещаться в базовую роль свидетельства:

- сила;
- надёжность;
- качество;
- уверенность;
- независимость;
- вес;
- вероятность;
- итоговая убедительность.

Если они необходимы, они ДОЛЖНЫ представляться через `005-ASSESSMENT` или соответствующий специализированный механизм.

ИИ-оценка, релевантность поиска, сходство текста, число совпадений или машинная уверенность НЕ становятся автоматически оценкой качества свидетельства.

---

## 13. Происхождение и история записи

Происхождение записи использования свидетельства и происхождение источника — разные вещи.

Создатель записи НЕ является автоматически автором источника.

Импортировавшая система НЕ является автоматически субъектом доказательного использования.

Публикация или хранение записи НЕ являются автоматически актом использования свидетельства.

Исправление записи ДОЛЖНО сохранять историю изменения.

Если исправление меняет сам факт исторического использования свидетельства, необходимо различать исправление записи и новый доказательный акт.

---

## 14. Утрата и неизвестность

Источник МОЖЕТ быть:

- утрачен;
- недоступен;
- частично сохранён;
- известен по вторичным сообщениям;
- известен только по фрагменту;
- исторически использован, но сейчас недоступен.

Такая ситуация НЕ ДОЛЖНА приводить к удалению исторического использования свидетельства.

Неизвестная часть контекста ДОЛЖНА оставаться неизвестной.

Неизвестность НЕ ДОЛЖНА заменяться текущим состоянием источника, предположенной областью или вымышленной цепочкой происхождения.

---

## 15. Дедупликация

Дедупликация НЕ ДОЛЖНА уничтожать:

- идентичность;
- происхождение;
- историческое состояние;
- область свидетельства;
- историю записи;
- различия экземпляров;
- сведения о зависимости.

Одинаковое содержание НЕ является достаточным основанием для объединения двух источников или двух использований свидетельства.

Объединение записей НЕ ДОЛЖНО создавать ложное впечатление независимости.

---

## 16. Жизненный цикл

Использование свидетельства МОЖЕТ иметь исторические состояния записи.

Изменение состояния записи НЕ ДОЛЖНО уничтожать предыдущее состояние.

Отозванное, исправленное, неподтверждённое, недоступное или спорное использование НЕ следует переписывать в состояние, будто его никогда не существовало.

Исправление и создание нового доказательного акта ДОЛЖНЫ различаться.

Непрерывный жизненный цикл МОЖЕТ быть задан профилем, если профиль определяет критерии непрерывности и переходы состояний.

Профиль НЕ МОЖЕТ ослаблять базовые требования настоящего стандарта.

---

## 17. Полный обратный проход

Соответствующее использование свидетельства ДОЛЖНО позволять восстановить, насколько это возможно:

```text
Утверждение
  ↓
Использование свидетельства
  ↓
Идентичность источника
  ↓
исторически значимое состояние
  ↓
выражение / представление / экземпляр
  ↓
область / локатор / якорь
  ↓
происхождение / производность
```

Если какой-либо уровень неизвестен, это ДОЛЖНО быть явно представимо.

Наличие технической ссылки без возможности понять, какой материал использовался, НЕ является полноценной трассируемостью.

---

## 18. Соответствие стандарту

Запись соответствует настоящему стандарту, если она:

1. является специализированной записью;
2. имеет одну разрешимую идентичность источника;
3. имеет одну семантически определённую область свидетельства;
4. имеет одно целевое утверждение;
5. имеет одну базовую роль `supports` или `contradicts`;
6. не смешивает свидетельство с оценкой;
7. сохраняет материально необходимый исторический контекст;
8. не подменяет неизвестность текущими значениями;
9. сохраняет существенную производность;
10. сохраняет историю записи;
11. не создаёт ложную независимость;
12. не превращает поиск в свидетельство автоматически;
13. не превращает «не найдено» в «отсутствует» автоматически;
14. допускает обратный проход к источнику и области;
15. остаётся интерпретируемой без обязательной зависимости от одной программной платформы.

---

## 19. Архитектурные стресс-тесты

Стандарт СЛЕДУЕТ проверять как минимум на следующих случаях:

1. один источник используется для двух разных утверждений;
2. один фрагмент используется для двух разных утверждений;
3. источник позже изменён;
4. источник утрачен;
5. источник никогда не был доступен полностью;
6. известна только поздняя копия;
7. имеется OCR с ошибками;
8. имеется перевод;
9. имеется производное представление;
10. имеется составной источник;
11. результат поиска ничего не обнаружил;
12. отсутствие объекта зависит от возможности его обнаружить;
13. два источника имеют одинаковое содержание;
14. два источника имеют общего предка;
15. несколько источников повторяют одно сообщение;
16. имеется циклическая сеть цитирования;
17. идентичность источника спорна;
18. область свидетельства неизвестна;
19. текущая версия источника отличается от исторически использованной;
20. запись была исправлена;
21. запись была импортирована из другой системы;
22. источник доступен только через устаревшую технологию;
23. свидетельство оценивается повторно;
24. используется ИИ для поиска или извлечения;
25. архив повреждён или неполон.

Если принятие сценария требует нарушения базовых границ, архитектура требует пересмотра.

## 20. Итоговые инварианты

**EU-01.** Использование свидетельства является специализированной записью.

**EU-02.** Использование свидетельства НЕ является источником.

**EU-03.** Использование свидетельства НЕ является утверждением.

**EU-04.** Использование свидетельства НЕ является оценкой.

**EU-05.** Атомарное использование имеет ровно одну идентичность источника.

**EU-06.** Атомарное использование имеет ровно одну область свидетельства.

**EU-07.** Атомарное использование имеет ровно одно целевое утверждение.

**EU-08.** Атомарное использование имеет ровно одну базовую роль.

**EU-09.** Базовые роли — только `supports` и `contradicts`.

**EU-10.** Сила свидетельства не является его базовой ролью.

**EU-11.** Надёжность свидетельства не является его базовой ролью.

**EU-12.** Независимость не является его базовой ролью.

**EU-13.** Неуказанная область НЕ означает автоматически весь источник.

**EU-14.** Контекст источника является контекстом разрешения, а не обязательной отдельной сущностью.

**EU-15.** Состояние источника не равно версии записи источника автоматически.

**EU-16.** Текущее состояние источника НЕ заменяет исторически использованное состояние автоматически.

**EU-17.** Поиск НЕ становится свидетельством автоматически.

**EU-18.** Наблюдение НЕ становится свидетельством автоматически без разрешимого источника, области, утверждения и роли.

**EU-19.** «Не найдено» НЕ означает автоматически «отсутствует».

**EU-20.** Отрицательное свидетельство требует соответствующего контекста обнаружения.

**EU-21.** OCR НЕ является автоматически оригинальным источником.

**EU-22.** Преобразование с потерями НЕ должно скрываться как полное совпадение с исходником.

**EU-23.** Адресуемый компонент НЕ становится автоматически самостоятельным источником.

**EU-24.** Происхождение целого НЕ переносится автоматически на каждую часть.

**EU-25.** Различие записей НЕ доказывает независимость.

**EU-26.** Разные источники НЕ являются автоматически независимыми.

**EU-27.** Повторение сообщения НЕ является автоматически независимым свидетельством.

**EU-28.** Зависимость и независимость относятся к отношениям и оценке, а не к базовой роли.

**EU-29.** Цитирование НЕ доказывает производность.

**EU-30.** Циклическая сеть ссылок сама по себе НЕ является доказательством ошибки.

**EU-31.** Замкнутая поддержка без достаточного внешнего или независимого основания НЕ должна выдаваться за независимое подтверждение.

**EU-32.** Историческое использование МОЖЕТ сохраняться после утраты источника.

**EU-33.** Недоступность источника НЕ уничтожает историческую запись автоматически.

**EU-34.** Неизвестное НЕ ДОЛЖНО заменяться предположением.

**EU-35.** Происхождение записи НЕ равно происхождению источника.

**EU-36.** Импорт НЕ доказывает авторство или использование свидетельства.

**EU-37.** Исправление записи НЕ должно уничтожать историю.

**EU-38.** Новое доказательное действие НЕ должно маскироваться под исправление старой записи.

**EU-39.** Дедупликация НЕ должна уничтожать происхождение.

**EU-40.** Дедупликация НЕ должна создавать ложную независимость.

**EU-41.** Исторический контекст должен сохраняться настолько, насколько он материален для свидетельства.

**EU-42.** Одна запись не должна использоваться как атомарная запись сразу для нескольких целевых утверждений.

**EU-43.** Один материал для нескольких утверждений требует отдельных контекстов использования.

**EU-44.** Ограничение или уточнение не являются третьей базовой ролью.

**EU-45.** Оценка силы, качества или уверенности не должна заменять запись использования свидетельства.

**EU-46.** Машинная уверенность ИИ не является автоматически доказательством.

**EU-47.** Результат поиска не является автоматически доказательством.

**EU-48.** Отсутствие идентификатора доказательства не является автоматически доказательством отсутствия.

**EU-49.** Полноценная трассируемость требует обратного прохода к источнику и использованной области настолько, насколько это возможно.

**EU-50.** Техническая ссылка без разрешимой семантической области не обеспечивает полной трассируемости.

**EU-51.** Профиль может усиливать Core, но НЕ может его ослаблять.

**EU-52.** Соответствие техническому формату НЕ означает автоматически эпистемическую корректность.

**EU-53.** Сохранение свидетельства должно быть отделено от утверждения об истинности целевого утверждения.

## 22. Статус

Версия 0.2 является рабочей нормативной редакцией.

Она НЕ считается окончательно замороженной только на основании редакционного аудита.

Перед переходом к следующему стандарту необходимо выполнить:

1. контрольный аудит всех 53 инвариантов;
2. сквозной аудит совместимости с 001–003;
3. сквозной аудит границы с 005;
4. повторную проверку исторического состояния источника;
5. повторную проверку отрицательного свидетельства;
6. повторную проверку зависимости и независимости;
7. повторную проверку преобразований и OCR;
8. повторную проверку обратного прохода;
9. контрольный языковой аудит;
10. только после этого — заморозку версии.
