005-ASSESSMENT.md

Статус: канонический стандарт v0.2
Проект: Энциклопедия цивилизации
Назначение: определить универсальную модель Оценка (оценивания) для утверждения, источники, использование свидетельстваs, методы, оценки, физических объектов, отношений, множеств и иных определённых объекты оценивания.

────────

0. Назначение стандарта

Оценка — специализированный запись, представляющий результат оценивания определённого объект оценивания относительно определённого оценочного конструкта.

Стандарт не определяет, что является истиной, не создаёт универсальной оценки истинности и не придаёт особого эпистемического статуса экспертам, государствам, институтам, проекту или автоматическим системам.

Он определяет, как Оценка должен быть представлен так, чтобы его смысл, границы применимости, происхождение и история могли быть честно восстановлены.

Каноническое ядро:

```text
ASSESSMENT

является специализированным Record

требует:
  ровно 1 определённую структуру Target
  ровно 1 основной Evaluation Aspect / оценочный конструкт

при завершении:
  ровно 1 определённый Assessment Result

может включать:
  0..N явно указанных Assessment Inputs

должен дополнительно сохранять или позволять разрешить:
  любой Context
  Scope
  Basis
  States
  версии
  происхождение
  цепочку происхождения результата

которые существенно необходимы
для корректной идентификации,
интерпретации,
сопоставимости,
воспроизводимости
или применимости Result.
```

────────

1. Ядро оценки

1.1. Оценка

Оценка — специализированный запись, представляющий один определённый акт оценивания или, если это заранее определено профиль, одну непрерывную оценочную сущность с сохраняемыми историческими состояния.

Оценка не является объект оценивания и не является его внутренним свойством.

```text
Assessment ≠ Target
```

Оценка также автоматически не является:

```text
Claim
Evidence Use
Measurement
Truth
Decision
Consensus
Authority
Project Endorsement
```

1.2. Минимальная структура

Завершённый Оценка ДОЛЖЕН иметь:

1. одну определённую структуру объект оценивания;
2. один основной Аспект оценивания / оценочный конструкт;
3. один определённый Результат оценивания.

Дополнительные элементы являются условно обязательными и включаются только тогда, когда без них существенно нарушается смысл Оценка.

1.3. Определённость

Определённость означает: имеющий достаточно определённую семантику для однозначной интерпретации в пределах применимого стандарта/профиля.

Определённое понятие не обязано существовать как отдельный запись.

1.4. Разрешимость

Разрешимость означает: объект, состояние, отношение или семантика могут быть однозначно установлены из сохранённой структуры, истории, происхождения или ссылок без изобретения отсутствующего смысла.

```text
разрешимость ≠ наличие текущего доступа онлайн
```

1.5. Существенная значимость / обязательность

Элемент является существенно значимым, если его отсутствие, изменение или неверное представление способно существенно изменить:

• идентичность;
• интерпретацию;
• сопоставимость;
• воспроизводимость;
• применимость;
• или оценку результат.

1.6. черновик и завершённый Оценка

Оценка запись в состоянии черновик/в процессе МОЖЕТ временно быть неполным согласно общему жизненному циклу запись.

Завершённый Оценка ДОЛЖЕН иметь определённый результат.

Отсутствие результат в черновике не делает сам запись невозможным; отсутствие результат в записи, заявленной как завершённый Оценка, является нарушением базового соответствия стандарту.

2. Объект оценивания

2.1. Структура объект оценивания

Каждый Оценка ДОЛЖЕН иметь ровно одну определённую структуру объект оценивания.

Это не означает наличие ровно одного объект оценивания запись.

Структура объект оценивания МОЖЕТ представлять:

• отдельный объект оценивания;
• адресуемый подцелевой объект;
• реляционный объект оценивания;
• объект оценивания на уровне множества.

2.2. Реляционный объект оценивания

Если оцениваемое свойство существует между несколькими участниками, объект оценивания МОЖЕТ быть реляционным:

```text
Target:
(EU-A, EU-B)

Aspect:
independence
```

Роли и порядок ДОЛЖНЫ быть разрешимы, если отношение асимметрично или порядок существенно влияет на смысл.

2.3. объект оценивания на уровне множества

Оценка МОЖЕТ оценивать множество как единый объект оценивания:

```text
Target:
[EU-1, EU-2, EU-3]

Aspect:
methodological diversity
```

Оценка на уровне множества НЕ ДОЛЖЕН использоваться для скрытого объединения независимых актов оценивания отдельных членов.

Определённый профиль коллективный предикат МОЖЕТ иметь следствия для членов множества, но:

```text
Assessment(set)
≠ автоматически совокупность Assessment(member)
```

2.4. Разнородные объекты оценивания

Структура объект оценивания НЕ ДОЛЖНА превращаться в произвольный контейнер семантически несвязанных объектов.

Если несколько участников входят в объект оценивания, их роли и общий оценочный смысл ДОЛЖНЫ быть определены.

2.5. Подцелевой объект

Если результат утверждается о самостоятельно адресуемом компоненте как об отдельном объекте оценивания, этот компонент СЛЕДУЕТ представлять как подцелевой объект.

Если компонент лишь ограничивает область рассмотрения свойства более широкого объект оценивания, МОЖЕТ использоваться оценивание область применимости.

2.6. Состояние объект оценивания

Если объект оценивания изменяем и его состояние существенно влияет на Оценка, соответствующее состояние объекта оценивания ДОЛЖНО оставаться разрешимым.

```text
Assessment(Target@v1)
≠ автоматически
Assessment(Target@v2)
```

Новое состояние объект оценивания НЕ ДОЛЖНО молча менять исторический Оценка.

2.7. Динамический объект оценивания

объект оценивания МОЖЕТ определяться посредством запроса, фильтра или процесса отбора.

Завершённый Оценка ДОЛЖЕН сохранять семантически замкнутый исторический объект оценивания через разрешённый состав либо достаточный неизменяемый контекст его восстановления.

Одна временная отметка сама по себе не гарантирует воспроизводимость исторического объект оценивания.

────────

3. Аспект оценивания, основание & результат

3.1. Аспект оценивания

Аспект оценивания определяет, какое свойство или оценочный конструкт оценивается.

Каждый Оценка ДОЛЖЕН иметь один основной Аспект оценивания / оценочный конструкт.

Семантика аспект ДОЛЖНА быть разрешима.

Перечни вроде надёжности, риска, качества, устойчивости, применимости и воспроизводимости являются примерами, а не закрытым словарём ядро.

3.2. Идентичность аспект и его обозначение

Обозначение не определяет семантическую идентичность.

```text
"надёжность"
"reliability"
"fiabilité"
```

МОГУТ представлять одну и ту же семантическую идентичность понятия.

3.3. Составной аспект

аспект СЛЕДУЕТ выражать оцениваемое свойство.

объект оценивания, контекст и область применимости СЛЕДУЕТ представлять собственными механизмами, если соответствующие семантические различия содержательно разделимы.

профили СЛЕДУЕТ определять каноническое представление для повторяющихся предметных шаблонов.

3.4. оценивание основание

оценивание основание — определённая оценочная логика, метод, система критериев, правило, модель, шкала или иная структура, по которой объект оценивания/входы интерпретируются в результат.

основание МОЖЕТ быть составным.

ядро не требует ровно одного метод.

основание МОЖЕТ включать критерий, метрика, порог, правило, шкала, вес, агрегация метод, методология, эталон, модель, формула или экспертную процедуру.

Эти элементы не являются универсально обязательными сущностями ядро.

3.5. основание ≠ входы ≠ происхождение

```text
Evaluation Basis
≠ происхождение Assessment Input
≠ происхождение выполнения
≠ происхождение Record
```

Семантическое различие не требует отдельных систем хранения.

Одна инфраструктура происхождения МОЖЕТ хранить несколько семантических слоёв.

3.5.1. критерий ≠ вход

критерий определяет, как или по какому условию производится оценивание.

вход определяет, какой материал фактически используется при оценивании.

```text
Criterion ≠ Input, удовлетворяющий Criterion
```

критерий и фактический материал, использованный для проверки критерий, ДОЛЖНЫ оставаться семантически различимыми.

3.6. Результат оценивания

Завершённый Оценка ДОЛЖЕН иметь ровно один определённый Результат оценивания.

результат МОЖЕТ быть качественным, категориальным, порядковым, числовым, вероятностным, интервальным/распределительным, сравнительным, ранжированным, текстовым или структурированным.

Тип данных не определяет онтологию.

3.7. Структурированный результат

Структурированный результат допустим, если его компоненты образуют один определённый профиль согласованный оценочный конструкт.

Структурированный результат НЕ ДОЛЖЕН становиться произвольным контейнером.

Если компонент требует самостоятельной адресуемости, происхождения, конкурирующего оценивания или жизненного цикла, его СЛЕДУЕТ выделить в отдельный Оценка или иной явно представленный запись.

3.8. Семантика результат

результат ДОЛЖЕН быть интерпретируемым относительно аспект и существенно необходимых основание/шкала.

результат = 3 недостаточно определён, если неизвестно, что означает 3.

3.9. Порядок результат ≠ желательность

Упорядоченная шкала не означает автоматически положительную или отрицательную направленность.

Высокая надёжность, высокий риск и высокая неопределённость имеют разную семантику желательности.

ядро не предполагает универсальной монотонности.

3.10. измерение и Оценка

измерение и Оценка различаются семантикой, а не типом данных.

коэффициент ошибок = 4,2 % может быть измерением.

Если профиль определяет эту величину как оценочный результат, она МОЖЕТ быть результат Оценка.

Количественное выражение не даёт автоматического эпистемического превосходства.

4. Входные данные оценивания, свидетельство & происхождение

4.1. Вход оценивания

Вход оценивания — разрешимый информационный или фактический объект, содержание или состояние которого существенно используется при получении результат.

Оценка МОЖЕТ иметь 0..N явно указанных входы.

Явно указанные входы не являются универсальным требованием ядро.

4.2. Допустимые входы

Вход оценивания МОЖЕТ быть использование свидетельства, источник, утверждение, измерение, набор данных, результатом метод, другим Оценка, производным значением или иным определённым объектом.

4.3. использование свидетельства и Вход оценивания

Если материал используется как атомарное свидетельство относительно утверждение, СЛЕДУЕТ использовать использование свидетельства.

Если материал является техническим или оценочным входом процесса Оценка, он МОЖЕТ быть прямым Вход оценивания.

```text
Evidence Use
≠ Assessment Input
```

использование свидетельства МОЖЕТ быть Вход оценивания.

4.3.1. цитирование/ссылка ≠ вход принадлежность

Наличие источник, утверждение или иного запись в цитате, обосновании, обсуждении или ссылке НЕ ДОЛЖНО автоматически означать принадлежность к Вход оценивания.

Фактическая роль объекта — вход, объект оценивания, ссылка на основание, цитата, ссылка на происхождение или иная роль — ДОЛЖНА оставаться разрешимой, когда различие существенно важно.

```text
citation/reference
≠ автоматически Assessment Input
```

4.4. объект оценивания как неявный вход

Если Оценка непосредственно использует свойства объект оценивания, которые уже разрешимы через ссылку на объект оценивания, отдельная дублирующая ссылка вход не обязательна.

4.5. Исторические входы

Завершённый Оценка ДОЛЖЕН сохранять фактически использованную историческую основу входных данных, если она существенно значима.

Новый вход НЕ ДОЛЖЕН молча добавляться к старому завершённому Оценка.

Динамический отбор вход ДОЛЖЕН сохранять состав или достаточный неизменяемый контекст его восстановления, если состав существенно влияет на результат.

4.6. Состояние вход

Существенно значимое состояние входа ДОЛЖНО оставаться разрешимым.

Для Вход оценивания, который является источник, состояние входа ДОЛЖНО быть семантически отличимо от версии записи источник. Если исторически значимое состояние самого источник существенно влияет на результат, именно это состояние источник ДОЛЖНО оставаться разрешимым.

Для входа оценивания, который является использованием свидетельства, исторически значимый контекст источника, включая состояние источника и иные уровни источника, ДОЛЖЕН оставаться разрешимым настолько, насколько они существенно необходимы для интерпретации фактически использованного свидетельства. Оценка НЕ ДОЛЖНА заменять такую историческую определённость текущей версией записи источника или текущим состоянием источника.

```text
Input@v3
≠ Input@current автоматически

версия записи Source
≠ состояние Source автоматически
```

4.7. Отсутствующие значения

Необходимо различать отсутствующее, неизвестное, не измерялось, неприменимо, ноль, не обнаружено, исключено.

Эти состояния НЕ ДОЛЖНЫ молча сливаться, если различие существенно важно.

4.8. Происхождение отбора

Критерий отбора МОЖЕТ быть частью основание.

Выполнение отбора относится к процессу и его происхождению.

Выбранные объекты являются входы.

Эти роли ДОЛЖНЫ оставаться различимыми.

4.9. Цепочка происхождения результат

СЛЕДУЕТ различать:

```text
Record происхождение
Evaluation execution происхождение
Input selection происхождение
Result derivation lineage
```

Но ядро не требует отдельного механизма хранения для каждого слоя.

4.10. Преобразования

Существенно значимые фильтрация, нормализация, импутация, взвешивание или иное преобразование между входы и результат ДОЛЖНЫ оставаться разрешимыми.

4.11. Зависимость

Различные Оценка ID или разные идентичности рецензентов сами по себе не устанавливают независимость.

```text
неизвестная зависимость
≠ независимость
```

Зависимость МОЖЕТ быть частичной, попарной, относительной к методологии, относительной к источнику или неизвестной.

Ядро не требует универсального двоичного значения поля независимости `true/false`.

4.12. Самообоснование

Оценка НЕ ДОЛЖЕН использовать собственный результат как независимое свидетельское обоснование того же результат.

Определённое рекурсивное вычисление или вычисление с фиксированной точкой МОЖЕТ существовать, если рекурсия является частью явно заданной оценивание основание и не представляется как независимое подтверждение.

Косвенные циклы зависимости ДОЛЖНЫ оставаться обнаруживаемыми, когда это существенно важно.

5. Идентичность, жизненный цикл и повторное оценивание

5.1. Идентичность оценки

Оценка имеет постоянную идентичность запись, унаследованную от общей инфраструктуры запись.

Идентичность НЕ ДОЛЖНА вычисляться из объект оценивания + аспект + результат или других семантических кортежей.

Одинаковый результат ≠ один и тот же Оценка.

5.2. Дискретный Оценка

Дискретный Оценка обычно представляет один исторический акт оценивания.

5.3. исправление

исправление исправляет представление того же акта оценивания.

Если действие действительно является исправление, идентичность Оценка ДОЛЖНА сохраняться.

Примеры: ошибка транскрипции, ошибочная ссылка, обогащение метаданных, уточнение без нового оценочного рассуждения.

Если исправление меняет акт оценивания настолько, что возникает новый акт оценивания, оно ДОЛЖНО рассматриваться как Повторное оценивание или иной новый Оценка, а не как исправление.

5.4. Повторное оценивание

Повторное оценивание — новый акт оценивания.

Повторное оценивание ДОЛЖЕН иметь новую идентичность Оценка.

Исключение не допускается за счёт переименования Повторное оценивание в обновление состояние. Если заранее определённый профиль поддерживает Непрерывное оценивание с одной постоянной идентичностью, последующее вычисление или обновление, являющееся частью этой непрерывной идентичности, не является Повторное оценивание в смысле настоящего раздела.

Один и тот же оценщик МОЖЕТ создать новый Оценка.

5.5. проверка ≠ Повторное оценивание

проверка имеет объект оценивания = предыдущая Оценка и оценивает сам Оценка.

Повторное оценивание имеет объект оценивания = исходный/связанный объект оценивания и оценивает объект оценивания заново.

Один процесс МОЖЕТ породить обе записи.

5.6. Непрерывное оценивание

профиль МОЖЕТ определить постоянно поддерживаемую идентичность Оценка.

В этом случае повторные вычисления МОГУТ быть историческими состояниями одной идентичности Оценка.

Непрерывная цепочка происхождения ДОЛЖНА быть определена до или независимо от конкретного изменения результат и НЕ ДОЛЖНА объявляться задним числом только для избежания новой идентичности.

Исторические состояния непрерывного оценивания ДОЛЖНЫ сохранять существенно значимое состояние объекта оценивания, состав и состояния входов, версию основания и метода, контекст и результат.

5.7. Цепочка идентичности ≠ цепочка переоцениваний

Связанные повторные оценивания МОГУТ образовывать историческую цепочку, но это не означает одну идентичность Оценка.

```text
цепочка связанных переоцениваний
≠ одна идентичность Assessment
```

5.8. Замещение

Оценка МОЖЕТ быть замещён другим Оценка.

```text
замещён
≠ удалён
≠ ложен
```

Замещение СЛЕДУЕТ связывать с разрешимой областью и контекстом, если оно не является универсальным.

ядро НЕ ДОЛЖЕН предполагать наличие одного глобально текущего Оценка.

5.8.1. Ветвящееся замещение

Замещение МОЖЕТ быть ветвящимся и относительным к профиль/контекст.

```text
Assessment A
├── Assessment B предпочтителен при Profile P1
└── Assessment C предпочтителен при Profile P2
```

ядро НЕ ДОЛЖЕН предполагать одну глобальную линейную цепочку «старый → новый → единственно действительный».

5.8.2. Отзыв

Оценка МОЖЕТ быть отозван.

```text
отозван
≠ удалён
≠ ложен
```

Отзыв означает изменение состояния жизненного цикла или операционного статуса, а не автоматически утверждение о ложности результат.

Существенно важная причина отзыва СЛЕДУЕТ сохраняться прослеживаемой, если это допускается применимыми ограничениями законодательства, конфиденциальности или безопасности.

Исторический Оценка СЛЕДУЕТ сохранять, если это разрешено. Если внешнее обязательное ограничение требует физического удаления, такое удаление НЕ ДОЛЖНО маскироваться под обычное исправление или переоценивание.

5.9. Последний / предпочтительный / применимый / активный

```text
последний
≠ предпочтительный
≠ применимый
≠ активный
≠ истинный
```

«Текущее» не является понятием ядра без определённой семантики профиля.

5.10. Миграция

Миграция носителя, сериализация или транспорт импорта не являются Повторное оценивание.

носитель ≠ идентичность оценки.

6. Контекст, применимость и область оценивания

6.1. Контекст оценки

Контекст оценки — внешние условия, назначение и ограничения применения, относительно которых должен интерпретироваться результат.

контекст является условно обязательным.

Если без него результат существенно меняет смысл или может быть неправильно применён, контекст ДОЛЖЕН быть разрешимым.

6.2. контекст ≠ объект оценивания

объект оценивания отвечает: что оценивается?

контекст отвечает: при каких внешних условиях и для какого применения?

Если второй участник является частью самого оцениваемого отношения, СЛЕДУЕТ использовать реляционный объект оценивания.

6.3. оценивание область применимости

оценивание область применимости — внутренняя граница фактически выполненной задачи оценивания.

область применимости является условно обязательным, если объект оценивания + аспект недостаточно точно задают границу оценивания.

6.4. контекст ≠ область применимости

```text
Context
→ внешние условия применения

Scope
→ внутренняя область того, что фактически оценивалось
```

6.5. Применимость

применимость не является универсальным внутренним логическим значением Оценка.

Результат интерпретируется внутри собственной исходной семантической границы без требования отдельной универсальной оценки применимости.

Отдельный вопрос применимости возникает прежде всего при повторном использовании или переносе существующего результата за пределы исходной семантической границы — например, на другой объект оценивания, состояние, контекст или вариант применения.

Она МОЖЕТ быть определённым профиль правилом отображения, отдельным Оценка или явно определённым выводом.

6.6. Перенос между контекстами

результат НЕ ДОЛЖЕН автоматически переноситься между существенно различающимися утверждения, совокупностями, предметными областями, контексты, состояниями объект оценивания или версиями.

Повторное использование между контекстами МОЖЕТ происходить только при разрешимой семантической эквивалентности, наличии правила переноса, отображения или отдельного шага рассуждения.

Сопоставимость и переносимость МОГУТ зависеть от аспект.

6.7. Наследование контекст

контекст МОЖЕТ наследоваться из профиль.

Существенно значимый унаследованный контекст ДОЛЖЕН разрешаться к историческому состоянию профиль/контекст, фактически применявшемуся к Оценка.

6.8. Динамический контекст

Динамические обозначения вроде «действующее законодательство», «действующий стандарт», «текущий уровень риска» НЕ ДОЛЖНЫ молча менять семантику исторического Оценка.

6.9. Временные роли

СЛЕДУЕТ различать время создания Оценка, время состояния объект оценивания и период применимости.

6.10. Географические роли

СЛЕДУЕТ различать местоположение оценщика, местоположение объект оценивания и географию применимости.

6.11. семантическая граница

семантическая граница — аналитическое понятие, а не ядро-сущность и не обязательное поле.

Концептуально:

```text
Semantic Envelope
=
Target
+
существенно значимое состояние Target
+
основной Evaluation Aspect / construct
+
Evaluation Scope, если существенно
+
Assessment Context, если существенно
+
те семантические элементы Basis, которые существенно ограничивают
интерпретацию, сопоставимость или применимость
```

Входные данные оценивания автоматически не входят в семантическую границу, поскольку относятся прежде всего к выводу результата.

```text
Semantic Envelope
≠ Basis вывода Result
```

6.12. Выход за семантическую границу

Результат НЕ ДОЛЖЕН молча переноситься за пределы собственной семантической границы без определённого отображения, вывода, оценки или правила профиля.

7. Качество Оценка, неопределённость и уверенность

7.1. Оценка для Оценка

Оценка МОЖЕТ быть объект оценивания другого Оценка.

Новая сущность метаОценка не требуется.

7.2. Отсутствие привилегии мета-уровня

```text
meta-level
≠ эпистемическая привилегия
```

Оценка для Оценка МОЖЕТ быть ошибочным и сам МОЖЕТ быть пересмотрен.

7.3. Качество ≠ корректность

```text
качество Assessment
≠ корректность Result
```

Хорошая методология не гарантирует истинный или корректный результат.

Корректный результат не доказывает хорошую методологию.

7.4. Метааспекты

Аспекты, связанные с качеством, МОГУТ включать методологическую адекватность, устойчивость, воспроизводимость, прозрачность, прослеживаемость, риск смещения, калибровку, применимость и уверенность.

Этот список является иллюстративным, а не словарём ядро.

7.5. Слои неопределённости

СЛЕДУЕТ различать неопределённость объект оценивания, неопределённость вход, неопределённость результат, уверенность в результат, уверенность модели и неопределённость применимости.

Неопределённость и уверенность ДОЛЖНЫ иметь разрешимый референт.

7.6. Вероятность ≠ уверенность

```text
P(Claim true)
≠ уверенность в оценке
≠ уверенность модели
```

Одинаковый числовой диапазон не означает одинаковой семантики.

7.7. Уверенность ≠ обратная неопределённость

ядро НЕ ДОЛЖЕН предполагать, что уверенность = 1 - неопределённость.

Высокая неопределённость объект оценивания МОЖЕТ сосуществовать с высокой уверенностью в том, что неопределённость действительно высока.

7.8. Представление уверенности и неопределённости

профиль МОЖЕТ представлять уверенность/неопределённость как структурированный компонент результат, отдельный Аспект оценивания или мета-Оценка.

ядро не требует избыточного представления.

7.9. Распространение

Качество, уверенность, неопределённость и иные свойства Оценка НЕ ДОЛЖНЫ автоматически складываться или распространяться через входы, методы, объекты оценивания или мета-уровни без определённого оценочного правила.

7.10. Рекурсивный обзор

Рекурсивное оценивание МОЖЕТ существовать, но рекурсивное замыкание не является требованием ядро.

Глубина мета-обзора определяется требованиями профиль и уровнем риска.

ядро не требует устранения всей неопределённости.

Принцип остановки для высокого риска: выполнять предусмотренные профиль требования к обзору, независимости, обработке неопределённости, валидации и воспроизводимости, а не продолжать обзор бесконечно.

8. агрегация, сравнение & синтез

8.1. Сравнение ≠ агрегация

Сравнение отвечает на вопрос: насколько оценки отличаются и сопоставимы?

Агрегация отвечает на вопрос: можно ли получить новый результат из нескольких входы?

8.2. Синтез

синтез — более широкая категория процесса/функции, а не обязательная сущность ядро.

```text
оценочный синтез → Assessment
выводный синтез → Inference / Argument
синтез с выбором действия → Decision
```

Один процесс МОЖЕТ порождать несколько записи.

8.3. Агрегированный Оценка

агрегированный Оценка — обычный Оценка, использующий предыдущие оценки и/или другие объекты как входы.

Универсальная сущность агрегированныйОценка не требуется.

Статус агрегированного Оценка не даёт автоматического эпистемического превосходства.

8.4. Необязательность агрегации

Несколько оценки МОГУТ сосуществовать без единого агрегированного результат.

Множественность является допустимым состоянием знания.

8.5. Большинство / последний / авторитет

ядро не использует правила «побеждает большинство», «побеждает последний», «побеждает авторитет», «побеждает проект» как универсальную эпистемическую семантику.

Голосование МОЖЕТ быть методом агрегации, определённым профиль, но число голосов не имеет универсального значения истинности.

8.6. Сопоставимость

Сопоставимость является относительной к выполняемой операции.

```text
сопоставимость для ранжирования
≠ сопоставимость для арифметического среднего
≠ сопоставимость для статистического объединения
```

Одинаковый аспект или одинаковое обозначение не гарантируют сопоставимости.

8.7. Синтез между аспект

Разные аспекты МОГУТ участвовать в новом Оценка при явно заданной оценочной модели.

Они НЕ ДОЛЖНЫ молча сводиться к одному показателю.

Если синтез выбирает действие, результат МОЖЕТ перейти в решение.

8.8. Недопустимая скаляризация

Скаляризация сама по себе допустима.

Недопустимая скаляризация — превращение многомерных, порядковых или иных не-скалярных результаты в скаляр без определённого семантически корректного отображения.

8.9. Перекрытие зависимостей

Агрегация ДОЛЖНА учитывать существенно значимое перекрытие зависимостей, а не только точное совпадение вход.

Повторное использование одного вход само по себе не запрещено.

Запрещено представлять повторный или зависимый вклад как независимую поддержку без определённого обоснования.

8.10. Усиление уверенности

Совпадающие оценки или оценки с высокой уверенностью НЕ ДОЛЖНЫ автоматически повышать агрегированную уверенность только из-за их количества.

8.11. Конфликт

Перед установлением содержательного конфликта СЛЕДУЕТ сравнить семантические границы.

Разный основание всё равно МОЖЕТ приводить к содержательному разногласию, если оцениваемый вопрос достаточно согласован.

Разногласие МОЖЕТ относиться только к отдельному компоненту.

Конфликт не требует принудительного разрешения.

8.12. Согласие ≠ истина

```text
90% согласия
≠ 90% вероятности истинности
```

Оценка консенсус/согласие НЕ ДОЛЖНА молча превращаться в вероятность истинности или уверенность.

8.13. Неопределённый итог

неопределённый результат МОЖЕТ быть допустимым результат, определённым профиль.

```text
нет агрегированного Assessment
≠ агрегированный Result = inconclusive
```

9. Соответствие, целостность и режимы отказа

9.1. Диагностические уровни

```text
1. Инварианты / онтология
2. Соответствие
   ├── структурное
   ├── ссылочное
   ├── семантическое
   └── контекстно-историческое
3. Целостность / происхождение
4. Эпистемический / методологический уровень
5. Управленческий / операционный уровень
```

Эти уровни МОГУТ пересекаться.

9.2. Соответствие ядро

Оценка соответствует ядро, если он представляет допустимый Оценка запись с разрешимыми объект оценивания и основным аспект/конструктом, с определённым результат, если Оценка завершён, и с достаточной структурной, ссылочной, семантической и контекстно-исторической разрешимостью всех существенно необходимых элементов.

9.2.1. Структурное соответствие

Структурное соответствие относится к обязательной структуре, количественным ограничениям, допустимым формам и полноте жизненного цикла Оценка запись.

9.2.2. Ссылочное соответствие

Ссылочное соответствие относится к корректной разрешимости существенно необходимых ссылок, включая объект оценивания, входы, состояния, профиль, шкала, метод и другие объекты, на которые имеются ссылки.

9.2.3. Семантическое соответствие

Семантическое соответствие относится к достаточной определённости и интерпретируемости аспект, результат, шкала, ролей и других существенно значимых семантик.

9.2.4. Контекстно-историческое соответствие

Контекстно-историческое соответствие относится к сохранению существенно необходимого контекст, область применимости, исторических состояния, версий и границ применимости, необходимых для честной интерпретации исторического результат.

Эти виды соответствия МОГУТ пересекаться; одна проблема МОЖЕТ затрагивать несколько уровней одновременно.

9.3. Соответствие ≠ корректность

```text
соответствие Ядро
≠ истина
≠ эпистемическое качество
≠ одобрение проекта
```

Соответствующий ядро Оценка МОЖЕТ быть методологически слабым.

Эпистемически правдоподобный Оценка МОЖЕТ не соответствовать требованиям запись.

9.4. Нарушение целостности / происхождения

Нарушение целостности — несоответствие зарегистрированных идентичности, происхождения, входы, авторства, истории или цепочки вывода тому, что фактически произошло или должно быть разрешимо.

Нарушение целостности не требует доказательства злого умысла.

```text
ошибка ≠ мошенничество
```

9.5. Повреждённая и сфабрикованная ссылка

```text
недоступная ссылка
≠ сфабрикованная ссылка

отсутствующее происхождение
≠ ложное происхождение
```

9.6. Эпистемический / методологический отказ

Оценка МОЖЕТ соответствовать ядро и при этом иметь смещение отбора, неподходящий метод, ошибочный вывод, неверные допущения, необоснованное обобщение или плохую статистику.

Это отдельный уровень.

9.7. Управленческий / операционный отказ

Относится к публикации, фильтрации, предпочтениям, представлению в интерфейсе, заявлениям об экспорте/импорте, удалению, одобрению и операционному использованию.

Канонический запись МОЖЕТ соответствовать стандарту при вводящем в заблуждение интерфейсном представлении.

9.8. Таксономия антишаблонов

9.9. Семантическая подмена

Явно определённое отображение, вывод или правило профиль МОЖЕТ законно преобразовывать семантику.

9.10. Подмена жизненного цикла

Новый акт оценивания НЕ ДОЛЖЕН маскироваться под простое исправление.

К этому относятся скрытый Повторное оценивание, фиктивный исправление и пересмотр подмена.

9.11. Смещение состояния / версии

Историческая оценка НЕ ДОЛЖНА молча переинтерпретироваться через существенно отличающиеся состояние объекта оценивания, состояние входа, версию шкалы, версию профиля, определение контекста или версию метода.

9.12. Точность представления

Соответствие канонического Оценка и точность его представления различаются.

Представления с потерями МОГУТ быть допустимы.

Нарушение возникает, если представление заявляет полную точность, но существенно необходимая семантика потеряна; применимый профиль требует более высокой точности; либо представление создаёт существенно вводящую в заблуждение интерпретацию.

9.13. Отбор / фильтрация

Показ одного Оценка из многих сам по себе не является нарушением.

Нарушение возникает, если представление ложно утверждает отсутствие альтернатив или консенсуса либо нарушает объявленную семантику профиль/управления.

9.14. Импорт

Неизвестная семантика импортированного материала ДОЛЖНА оставаться неизвестной.

Импорт с потерями или частичный импорт МОЖЕТ существовать, но НЕ ДОЛЖЕН заполнять отсутствующую семантику догадкой и заявлять полную эквивалентность Оценка.

9.15. Влияние вниз по цепочке

Исправление или отзыв исходного объекта НЕ ДОЛЖНЫ молча изменять исторические результаты объектов, зависящих от него.

Зависимость нижнего уровня, затронутая изменением, МОЖЕТ потребовать проверка/Повторное оценивание.

```text
затронут
≠ автоматически недействителен
```

Известные существенно значимые зависимости нижнего уровня СЛЕДУЕТ делать обнаруживаемыми; профиль МОЖЕТ повысить это требование до ДОЛЖЕН.

10. Выводы стресс-тестирования ядро

Эта глава фиксирует результаты системного стресс-тестирования и не вводит новых сущностей ядро.

10.1. Минимальный экспертный Оценка — ПРОЙДЕНО

Простой качественный Оценка без числовой оценки и без явно указанных входы МОЖЕТ соответствовать ядро.

10.2. Машинный Оценка — ПРОЙДЕНО

Машинный Оценка использует тот же ядро и не получает эпистемической привилегии.

10.3. Изменяемый объект оценивания/вход — ПРОЙДЕНО

Исторические состояния остаются разрешимыми и не следуют за текущим состояние автоматически.

10.4. Реляционные / множественные объекты оценивания — ПРОЙДЕНО

Допустимы при определённой семантике объект оценивания.

10.5. Динамический отбор объект оценивания/вход — ПРОЙДЕНО

Исторический состав ДОЛЖЕН быть замкнут или восстанавливаем, если он существенно важен.

10.6. Вероятностные / качественные / структурированные результаты — ПРОЙДЕНО

ядро не зависит от одной математической онтологии.

10.7. Непрерывный Оценка — ПРОЙДЕНО

Допустим при определённом профиль жизненном цикле и сохранении исторических состояния.

10.8. Мета-Оценка — ПРОЙДЕНО

Отдельная сущность не требуется.

10.9. Конфликтующие оценки — ПРОЙДЕНО

Множественность без принудительного консенсуса является допустимым состоянием знания.

10.10. Агрегация — ПРОЙДЕНО

агрегированный Оценка является обычным Оценка; агрегация необязательна.

10.11. Офлайн-сохранение — ПРОЙДЕНО

Ядро оценки не зависит от URL, HTTP, JSON, GitHub или иной текущей технологии.

10.12. Многоязычное представление — ПРОЙДЕНО

Язык обозначения не определяет семантическую идентичность.

10.13. Физические / нецифровые объекты оценивания — ПРОЙДЕНО

объект оценивания не обязан быть цифровым объектом.

10.14. Исторически неизвестная семантика

Если сохранена запись объект оценивания: S / значение: 4, но аспект/шкала неизвестны, система ДОЛЖНА сохранять неизвестность семантики вместо догадки.

10.15. Полная точность

Полная точность означает семантическую восстанавливаемость, а не побитовую идентичность.

Разные представления на разных носителях МОГУТ представлять один Оценка.

10.16. Проверка самоавторитета проекта — ПРОЙДЕНО

Оценка, созданный или предпочтённый проектом, не становится истина автоматически.

10.17. Расширяемость профиль — ПРОЙДЕНО

Будущие профили МОГУТ добавлять новые аспекты, методы, шкалаs, требования к проверка и модели уверенности без переписывания ядро.

15. Итоговая модель ядро

```text
ASSESSMENT
│
├── унаследованная идентичность Record / применимые правила Record
│
├── структура Target                    обязательна
├── основной Evaluation Aspect          обязателен
├── Assessment Result                   обязателен для завершённого
│
├── Assessment Inputs                   0..N явно указанных
│
├── Evaluation Basis                    условно
├── Assessment Context                  условно
├── Evaluation Scope                   условно
│
├── состояния Target / Input            условно
├── версии Method / Scale / Profile     условно
│
├── происхождение отбора / выполнения   условно
└── цепочка происхождения Result        условно
```

Принцип минимализма:

> **Чем сложнее конкретная оценка, тем больше контекста, входов, основания, происхождения и истории может быть существенно необходимо. Но сложность конкретной оценки не должна становиться обязательной сложностью каждой оценки.**

Принцип эпистемической честности:

> **Если система не может честно определить объект оценивания, оценочный конструкт, результат или существенно необходимую семантику, она должна сохранить неопределённость или неполноту, а не изобретать недостающий смысл.**
